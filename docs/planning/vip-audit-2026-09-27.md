# VIP audit and plan of action, 27 September 2026

A full-app review done three weeks after launch. It combines four sources: live production usage (Supabase), a screen-by-screen pass of the app at phone (390 px) and desktop (1440 px) widths, the code behind the core flows, and research into what competing apps do and what the reptile community praises or complains about. The launch review (`launch-review-2026-09-04.md`) and the mobile audit (`mobile-uiux-audit-2026-09-10.md`) covered security, performance and visual consistency. This one asks a different question: **why do people sign up and not come back, and what would make the core experience feel first class?**

1. Work on `main` (see CLAUDE.md).
2. Phase 0 and Phase 1 shipped on 27 September, along with the fixes from the functional audit (section 2A). Start at Phase 2 below.
3. The three decisions in section 5 were made on 27 September and are live. The Morph ID test set, label fixes and an evaluation workflow are in place (section 2A); the first full run was started on 28 Sep.

## 2A. Functional audit: does each tool actually work?

The first pass above measured usage and walked the screens. This pass checked whether the tools produce correct results, using the production database, the deployed code and the test suite. Morph ID was re-measured on 28 Sep with the new evaluation workflow (see "Evaluation" and "What the full run shows" below).

### Morph ID

- **The May score understated the model (re-measured 28 Sep, see "Evaluation").** The function's evaluation log (`geck_data.morph_eval_runs`) has 12 runs, all on 15 May 2026. The reference configuration matched the expected primary pattern (out of 23 classes) **30%** of the time on 100 photos; the best run reached 34%. Top-3 accuracy was never recorded. That score graded each photo against one pattern, and the one pattern was often not the breeder's (next bullet), so part of the "wrong" answers were patterns the breeder had tagged. Real weaknesses remain: Pinstripe was 0 for 16, and the model over-calls Harlequin.
- **The reference labels are breeder labels, and our import was mangling them (fixed 28 Sep).** The reference photos come from MorphMarket listings, tagged by the breeder selling that animal. Those tags are the best ground truth this hobby has. The problem was our conversion: when a breeder tagged more than one pattern, the import view kept whichever sorted first alphabetically. So "Dalmatian + Super Dalmatian" became Dalmatian (116 photos), and 1,291 photos (a third) got an arbitrary one of their tagged patterns. Now a stronger form wins over its base pattern (Super Dalmatian over Dalmatian, Extreme Harlequin over Harlequin, a Pinstripe variant over Pinstripe), every photo keeps the breeder's full list in `training_meta.breeder_patterns`, and relabeled rows keep their old label. Migration `20260928001246_breeder_label_fidelity`.
- **Test photos were leaking into retrieval (fixed 28 Sep).** The 220 test-split listings were indexed for photo-similarity search, so grading on them would let Morph ID look up the same gecko. Retrieval now skips the test split (1,693 photos remain searchable).
- **1,872 photo links were dead (fixed 28 Sep).** The second photo of each scraped listing still pointed at the old geck-data Supabase project, deleted after the 4 Sep consolidation. The files were already in this project's storage; the links now point there.
- **Tricolor counts as a Morph ID answer (decided 28 Sep).** MorphMarket's Morphpedia, Pangea and Moon Valley define Tricolor as three distinct colors in roughly equal amounts on a pattern (usually Harlequin), which argued for treating it as a color tag only. Tennyson's call: it is common enough, and sold as its own morph, that it counts. Morph ID (function version 56) can answer Tricolor, and also tags Tricolor next to the pattern when the three colors are present, the way breeders list "Tricolor Harlequin". 946 reference photos carry the Tricolor tag; 425 have Tricolor as their main label. The Morph Guide entry explains both. Migrations `20260928011231_tricolor_is_a_color` and `20260928014753_tricolor_counts_as_morph` (the second reverses the first except for the tag).
- **Class balance is uneven.** Harlequin, Extreme Harlequin and Dalmatian make up 59% of the 1,693 searchable photos. Flame has 1, Bicolor 1, Patternless 3, and 8 of the 23 pattern classes have none. More photos for those classes will help more than any prompt change.
- **The honesty design is good.** It refuses poor or wrong-subject photos, labels results "tentative" unless the model is confident and the retrieval agrees, lists up to three candidates with the visible evidence for each, separates what a photo shows from genetics, and never infers VCA or TSM Axanthic from a photo. That design is why a free first try is reasonable: a keeper sees a ranked shortlist with reasons, not a single confident wrong label.
- **The photo lookup had not been running (fixed 28 Sep).** Every identification tried to compare the photo with reference photos, but the Replicate account that makes photo fingerprints holds under $5 of credit, so Replicate allows one request at a time. Each lookup sent two (a first try at an endpoint this model does not have, then the real one), and the second was always refused. The lookup now sends one request (function version 59); a 3-gecko check went from 0 of 3 to 3 of 3. See "Needs Tennyson" in 2B about the credit.
- **Cost and speed:** about 3 cents and 30 seconds per identification with the photo lookup working (it adds three reference photos to each request). The May figures, 2 cents and 11 seconds, had no lookup.
- **Evaluation:** Actions > morph-id-eval runs the 220-gecko test set (`scripts/morph-id-eval/`), signs in as a dedicated evaluation account that skips credits and has no other rights, and saves results to `geck_data.morph_eval_runs`. It reports both "matches the picked pattern" and "matches any pattern the breeder tagged"; the second is the fair headline. First full run, 28 Sep (run 17, function version 59, Sonnet 4.6, 220 of 220 graded, 2 hours, about $6):

  | Measure | Result |
  |---|---|
  | First answer matches a pattern the breeder tagged | **43.6%** (45.6% when it gave an answer) |
  | A breeder-tagged pattern is in the top three | **68.6%** |
  | First answer matches the single picked pattern | 37.7% (May: 30% reference, 34% best, on a different 100-photo set) |
  | Picked pattern is in the top three | 64.1% |
  | Gave an answer rather than "insufficient evidence" | 67.7% (71 of 220 withheld) |
  | Photo lookup ran | 218 of 220 |

  By pattern (first answer matches a breeder tag): Harlequin 56 of 58, Super Dalmatian 13 of 18, Brindle 4 of 8, Extreme Harlequin 15 of 40, Dalmatian 7 of 25, Partial Pinstripe 1 of 5, and **Pinstripe 0 of 29, Tricolor 0 of 25, Quad Stripe 0 of 6, Tiger 0 of 5**. Most common misses: Extreme Harlequin called Harlequin (16), Tricolor called Harlequin (10), Pinstripe called Harlequin (9). The landing page should keep promising "a ranked shortlist with evidence", never "identifies your morph".
- **What the full run shows.**
  - *Morph ID defaults to Harlequin.* It answered Harlequin 148 times out of 220; Harlequin is the main label on 58 of the test geckos and tagged on 70. That is why Harlequin scores 56 of 58. It never once gave Pinstripe, Tricolor or Quad Stripe as its first answer. The May runs show the same pattern, so the photo lookup did not cause it.
  - *Pinstripe is a naming gap as much as a vision gap.* The model records pinning on its own axis ("pinning: full") and names the base pattern, so a Harlequin with full pinstripe comes back as "Harlequin". Breeders name that animal "Pinstripe". The eval now saves pinning, tags and the lookup's leader for each gecko in `morph_eval_runs.per_trait_metrics.rows`, so the next run will show how often the model saw the pinning and named it Harlequin anyway.
  - *The photo lookup finds what the model misses.* Graded on its own (one stored photo per test gecko, no model, no cost), the lookup's first pick matches a breeder tag 38.6% of the time and its top three 76.8%. It is weaker than the model on Harlequin (34 of 58) and stronger on Pinstripe (7 of 29 first, 19 of 29 in its top three, against the model's 0 and 4), Extreme Harlequin (22 of 40) and Tricolor (17 of 25 in its top three).
  - *Combining them, simulated on this run's answers:* keeping the model's first answer and filling the other two shortlist slots from the lookup puts a breeder-tagged pattern in the top three **77.3%** of the time, up from 68.6%. Letting the lookup replace the first answer does not help (41.8% to 44.5%).
  - *The prompt still calls breeder tags "weak evidence".* Both the retrieval note and the confidence rule tell the model that seller labels are weak and must never outweigh what it sees, and the lookup scores breeder labels at 0.40 out of 1. That predates the 28 Sep decision that breeder labels are high-quality ground truth. The weight does not change the lookup's ranking (nearly every reference photo is breeder-tagged), but the wording tells the model to discount the neighbors.
  - *The 2 lookup misses were Replicate cold starts.* Both calls took about 2.5 minutes while Replicate booted the model; the function then reported "Unrecognized Replicate embedding output shape", which misdescribes a timeout. Harmless, but the message should say "timed out"; fold it into the next deploy.
  - *Done 28 Sep (function version 60):* see the next two bullets.
- **Harlequin is the base (decided 28 Sep).** Tennyson's call: Harlequin is so common that most other morphs sit on top of it, so when anything else is present that name leads. Extreme and Super Harlequin are morphs in their own right and keep the lead. What changed:
  - *Reference labels.* When a breeder tagged Harlequin plus another pattern, the other pattern is now the main label: 143 photos moved to Pinstripe, 101 to Tricolor, 65 to Partial Pinstripe and a few to Tiger, Quad Stripe and others. Extreme Harlequin now wins over any other tagged pattern (46 photos moved from Brindle or Dalmatian). 372 photos in all, each keeping its old label; the test set's expected answers follow (20 changed). Migration `20260928172832_harlequin_is_the_base`.
  - *Morph ID's answer.* When the model names plain Harlequin but sees full, partial or quad pinning, or the tricolor look, that pattern leads and Harlequin stays second in the shortlist (`supabase/functions/_shared/morph-naming.ts`). The prompt states the same rule.
  - *The name on the result.* Lilly White, Axanthic, Cappuccino, Frappuccino, Soft Scale and White Wall lead the name when Morph ID sees them, and stack with any pattern other than plain Harlequin: "Pinstripe White Wall", "Tricolor Lilly White", "Axanthic Lilly White"; a Lilly White with harlequin patterning reads "Lilly White" with "Pattern underneath: Harlequin". Lilly White with Cappuccino reads as Frappuccino. Research for the stacking order: the most common breeder-tagged stacks among 9,920 MorphMarket listings are White Wall + Pinstripe (54), Lilly White + Pinstripe (35) and Soft Scale + Harlequin (27); titles put the pattern first about as often as not, so the name follows Tennyson's "Pinstripe White Wall"; "Axanthic Lilly White" outnumbers "Lilly White Axanthic" 66 to 29. `src/components/morph-id/morphHeadline.js`, with tests.
  - *Photo lookup.* The vote now runs over the 16 closest breeder photos, one per breeder. The old vote was capped at 2 photos per pattern out of 8, so no pattern could reach half the vote and the lookup never counted as agreeing: every run-17 answer was "tentative", none "best match". The shortlist fills slots two and three from this vote. The prompt no longer calls breeder tags weak, and breeder photos weigh 0.90 instead of 0.40. With the new labels the lookup alone puts a breeder-tagged pattern in its top three 73.6% of the time and gets Pinstripe right first 18 times out of 35 (it managed 7 of 29 before).
  - *Replicate cold starts* now report a time-out instead of "Unrecognized Replicate embedding output shape".
- **Second full run, 28 Sep (run 19, function version 60).** 195 of 220 graded. The last 25 failed because the Anthropic API account ran out of credit at 20:45 UTC (see Needs Tennyson). Expected answers now follow the Harlequin-base labels, so the "single picked pattern" rows are not comparable with run 17; the breeder-tag rows are.

  | Measure | Run 17 (v59) | Run 19 (v60) |
  |---|---|---|
  | A breeder-tagged pattern is in the top three | 68.6% | **72.8%** |
  | First answer matches a pattern the breeder tagged | 43.6% | 37.4% |
  | Gave an answer rather than "insufficient evidence" | 67.7% | **97.9%** |
  | First answer matches the single picked pattern | 37.7% | 28.7% |
  | Picked pattern is in the top three | 64.1% | 64.6% |

  - *The shortlist is better and nearly always given.* The top three now holds a breeder-tagged pattern 72.8% of the time, above the 68.6% bar, so the shortlist order stays (model's first answer, then the photo vote). Morph ID withheld an answer 4 times instead of 71.
  - *The first answer fell because v60 now answers the hard cases it used to withhold, and plain Harlequin is no longer a safe default.* It still names plain Harlequin 75 times against 35 geckos labeled that way: Extreme Harlequin called Harlequin 11 times, Pinstripe 9, Tricolor 6, Dalmatian 6, Brindle 5. It also reads partial pinning where breeders tagged full Pinstripe 8 times, and Tricolor as Extreme Harlequin 12 times.
  - *Letting the photo vote replace a Harlequin answer makes it worse* (37.4% to 34.4%): the vote leans Extreme Harlequin and Pinstripe on geckos breeders call Harlequin.
  - *Next change to test:* when the model reads partial pinning but the breeder photos vote Pinstripe, call it Pinstripe. Simulated on this run it lifts the first answer from 37.4% to 40.5% (6 gained, none lost). It was found on the test set itself, so it needs a fresh full run before it ships. The Tricolor-over-Extreme-Harlequin swap would add 3 more, but it goes against the 28 Sep decision that Extreme Harlequin keeps the lead, so it is left alone.

## 2. What the community celebrates (research)

Competitor pages that were blocked from direct fetching were read through search summaries. Sources are listed at the end.

### What keepers praise

- **"It keeps me on schedule."** The most common praise in App Store reviews for crested gecko care apps (Exotic Reptile Care, Shed, CareTrack, Husbandry.Pro) is reminders that arrive on the phone, when the app is closed. Per-animal feeding schedules and push reminders are the norm.
- **One-tap logging.** SnekLog's "Quick Feed" logs a whole room in one click once a typical meal is set. HerpTracker markets three-tap logging. Speed of the daily log is the retention loop.
- **Weight charts that mean something.** Keepers search for "crested gecko weight chart by age". A plain line of grams is less useful than "is this normal for a 9-month-old?".
- **Low commitment.** Several of the praised apps work without an account or offline. Geckistry's AI morph identifier is free.

### What breeders praise

- **QR tub labels that open a quick log.** MorphMarket's Label Creator prints QR labels from the animal record. Scanning one asks "Edit the animal or log a husbandry activity?". This is exactly how breeders work at a rack.
- **Hatch countdowns and pip alerts.** HatchLedger and Cltch both lead with this.
- **Hatchlings that inherit genetics automatically.** Log the clutch, the babies arrive with parents, possible hets and lineage filled in.
- **One-click buyer packet.** HatchLedger's most marketed sales feature: lineage, genetics, feeding, weights and shed history in one document for the buyer.
- **Waitlists with deposits.** Breed Ledger, HatchLedger and the new Day56 all lead with this. HatchLedger publishes a case study of a waitlist generating $40K in pre-sales.
- **Shared access.** HerpTracker and ReptiDex both sell collaborators (a partner or staff member logs too), with an activity log so nobody double-feeds.

### What people complain about (across the category)

- Records lost or reminders that do not fire. Spreadsheets win when an app is unreliable.
- Paywalls on basics (for example "more than 3 animals").
- MorphMarket: scams, uneven buyer protection, slow support. Trust is an open lane.

### Crested-gecko-specific practice the app should reflect

- **Fired up and fired down.** The community's standard advice is to judge color and pattern from photos taken both fired up and fired down. The Morph ID flow already asks for fire state; the add-gecko and listing flows do not.
- **Breeding readiness.** The widely repeated rule: females at 40 g or more (many breeders want 45 g) and at least 12 to 18 months old before pairing. NEHERP and most care sheets say this. The landing page slideshow already promises "breeding readiness", but the app only has a manual "Ready to Breed" status.
- **CGD brands.** Pangea and Repashy are the reference diets. Feeding logs should speak that language.

The gaps are not feature count. They are access, reliability of the daily loop, and focus.

## 3. Priority areas, ranked by need

Ranked by (evidence of pain) x (how many users it touches) / (effort). Status values: **Shipped 27 Sep**, **Decision needed**, **Next**, **Later**.

### P1. First-run activation: signup to first gecko to first photo

- **Evidence:** 2 of 3 new accounts never add a gecko. 1 photo uploaded in 30 days.
- **What we found:** After signup the path is a role question, then a tour, then a Dashboard whose top half is community totals, then a card that links to My Geckos (not to the add form), then a 20+ field form where photos are the last field. The landing page promises "log a gecko in under a minute".
- **What to change:**
  1. Every "add your first gecko" button opens the add form directly. **Shipped 27 Sep** (`/MyGeckos?add=1`).
  2. A short "quick add" for a first gecko: photo first, then name, sex ("Not sure" allowed), optional hatch date, weight and morph, plus "Remind me on feeding days". "More details" hands everything to the full form. Opens whenever the collection is empty. **Shipped 27 Sep** (`QuickAddGecko.jsx`, with tests)
  3. After the role question, keepers go straight to quick add; the tour stays in the sidebar. Breeders still get the tour. **Shipped 27 Sep**
  4. After the save, the quick add offers "Log today's weight" (if none was entered), "Try Morph ID free" (if no morph was entered), and "Add another gecko". **Shipped 27 Sep**
- **Done when:** at least 60% of new accounts add a gecko in their first session, and at least half of those include a photo.
- **Effort:** M.

### P2. Let people try Morph ID

- **Evidence:** 18 signed-in users opened Morph ID in 90 days; 6 identifications have ever run. Free accounts have 0 credits, so the flagship feature ends in an upgrade card for every free user. Geckistry's identifier is free. The July pricing decision (`docs/specs/pricing-decision-2026-07.md`) listed 1 free ID per month; the code later set it to 0.
- **What changed:** every free account gets one identification, ever. Enforced in `consume_morph_id_credit()` (tested on production in a rolled-back transaction: first call allowed, second refused, a refund restores the free try, paid tiers unchanged). The Morph ID page tells free and signed-out visitors their first identification is free, with photo tips to make it count; the pricing page and landing pill say so. Result screens already end with "Save as a new gecko".
- **Done when:** Morph ID runs per week is above the number of new signups per week.
- **Effort:** S once decided (one number in `src/lib/tierLimits.js`, mirrored in `consume_morph_id_credit()` and the `recognize-gecko-morph` function).
- **Status:** **Shipped 27 Sep.** See section 2A for why the result design matters here.

### P3. Reminders that work when the app is closed

- **Evidence:** feeding reminders run in `src/components/feeding/FeedingAlertSystem.jsx`, a 5-minute loop inside an open browser tab. Zero feeding-due notifications went out in the last 30 days. Hatch alerts and weigh-in reminders already run on a server schedule (pg_cron) and deliver by email and push through `notify_dispatch_on_insert`, so the pipe exists.
- **What changed:** `enqueue_feeding_reminders()` runs daily at 14:10 UTC (morning across the US). One combined message per keeper per day ("Adults and Juveniles are due for feeding today."), only for feeding groups and reptiles with reminders on, honoring the Settings switch and the late-reminder option. The in-tab loop no longer creates notifications, so nothing doubles. Dry run on production: one message for two due groups, none for a group not yet due or a muted group, none on a second run the same day.
- **Done when:** a keeper with a feeding group gets one reminder on the due day with the app closed, and none on other days.
- **Effort:** S to M (migration, function, cron entry, a Settings toggle).
- **Status:** **Shipped 27 Sep.** Note: no keeper currently has a feeding schedule (section 2A), so the quick add's reminder switch is what will start using this.

### P4. Dashboard: "your geckos today" first, community second

- **Evidence:** only 8 signed-in users opened the Dashboard in 90 days, while 22 opened My Geckos. The Dashboard's first screen on a phone is a large greeting and community totals (keepers, geckos, forum threads). The useful part, Next Actions (eggs near hatching, geckos not weighed in 30 days, pairings that went quiet), sits below the fold.
- **What to change:**
  1. Next Actions moves above the stats strip for signed-in keepers; the hero is smaller on phones. **Shipped 27 Sep**
  2. Guests were greeted as "Geck" (the fallback name "Geck Inspect User" cut to its first word). Guests and nameless accounts now get the greeting without a name. **Shipped 27 Sep**
  3. The Next Actions card is now "Today", and lists feeding days with a one-tap "Mark fed", next to eggs near hatch, weigh-ins due and stalled plans. Signed-in stat cards are all personal now (geckos, pairings, eggs incubating, hatched); "Forum Threads" was a sample capped at 10 labeled "Buzzing now". **Shipped 27 Sep**
- **Effort:** S (shipped part), M (Today card).

### P5. The gecko record: crested-first depth

These are the features that make a crested gecko keeper feel understood, and that multi-species competitors cannot copy cheaply.

1. **Breeding readiness badge on females.** Computed from the latest weigh-in and her age, using the care guide's numbers: 40 g and 18 months minimum, 45 to 55 g at 24 months or more ideal (this plan first said 12 months, which contradicted the guide). Verdicts: "Breeding ready", "Nearly ready" (within about 5 g and 3 months), "Not ready yet", each with what is missing ("37 g at 16 months. Needs 3 g more weight and 2 months more age."), plus a nudge when the last weigh-in is over 60 days old. Shown on the collection card (ready and nearly only, so juveniles are not all flagged), the gecko page and detail view (owner only), the dam list and a warning box in both pairing dialogs (Breeding and Breeding Pairs), and each Pairing Planner card. A test fails if the care guide's numbers change without the badge. Three blog passages told new breeders 35 g was enough; they now say 40 g, matching the guide. **Shipped 28 Sep** (`src/lib/breedingReadiness.js`)
2. **Healthy growth band on the weight chart.** Shade the typical crested gecko range by age behind the user's line so "is 18 g normal at 8 months?" answers itself. Source the band from the care guide's own numbers so the app does not contradict itself. **Next** (S)
3. **Fired-up and fired-down photo slots.** Two labeled photo slots on the add and listing forms, reusing the fire-state logic Morph ID already has. Buyers ask for both; the listing shows both. **Later** (M)
4. **Owner quick log from the QR passport.** When the owner scans a tub label, the passport page shows "Quick log: fed, weight, shed" at the top, opening Field Mode with that gecko selected. Today the owner sees buyer-facing content and two buttons at the bottom. **Next** (S)

## 5. Decisions (made 27 September, all three as recommended)

1. **Free Morph ID.** Options: (a) one free identification per account, ever; (b) one per month, as the July pricing doc proposed; (c) keep 0. Recommendation: (a). It costs a few cents per new account, answers Geckistry's free identifier, and ends the dead end 18 users hit.
2. **Server-side feeding reminders.** Recommendation: on for keepers who have set a feeding schedule, one batched message per day, with an off switch in Settings and in every message.
3. **Hide low-traffic pages from navigation.** Recommendation: hide the eight listed in P7 from the sidebar and command palette; keep their URLs working so nothing breaks for the few people who bookmarked them.
